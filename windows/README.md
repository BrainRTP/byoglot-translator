# ByoGlot for Windows

The portable core targets .NET 11 and has no Windows API or NuGet dependencies. It embeds shared contract data and language profiles directly from the repository. Run `dotnet test windows/ByoGlot.Core.Tests` from the repository root.

The toolchain is .NET SDK 11.0.100, C# 15, Windows App SDK 2.6.5 and Windows SDK 10.0.28000.0 with reference package 10.0.28000.87. The minimum OS build remains 10.0.26300.0. Versions live in `Directory.Packages.props`. `Directory.Build.props` declares the 28000 target before the SDK normalizes its supported targets because SDK 11.0.100 omits it. The VSTest-compatible xUnit package preserves the plan's `dotnet test` command on .NET 11.

`global.json` pins the SDK when commands run inside `windows/`. CI uses this file explicitly. The workflow also supports manual runs on development branches.

Capture integration must allocate a unique `long RequestId` for every trigger, including triggers after dismissal, and carry it from `QuickEvent.Captured` or `Clipboard` into `Finished` or `FailedWith`. Use the ID from the operation that completed, so a queued result cannot replace a newer translation, even when both requests have the same source text.

`CaptureInputs.CopyAndRead` returns `ClipboardRead`; `CaptureResult.Clipboard` preserves private and oversized fallback results. The copy fallback waits for 100 ms without a sequence change and an available clipboard, with a 1400 ms budget that includes late responses. Reads may trigger delayed rendering, so restoration compares owner and a SHA-256 content fingerprint under the clipboard lock rather than requiring the same sequence. Successful ByoGlot writes are marked before privacy classification and before their notifications reach `DoubleCopyDetector.Observe`.

`ByoGlot.App` contains the WinUI editor, connections, templates, settings and tray capture. Closing the main window hides it; Quit in the tray exits. Capture uses UI Automation on a background STA thread, then an optional Ctrl+C fallback. The fallback materializes every advertised clipboard format before copying and never snapshots protected content. It restores only when the current owner and content still match the captured copy, preserving newer content even from the same process. Snapshot, read and restore work runs on one background STA with a 500 ms operation deadline; timed-out snapshot results are disposed without sending Ctrl+C. Restore failure produces a localized clipboard warning. History and cloud upload are disabled for restoration and Copy, which use fully materialized Win32 clipboard data that remains available after exit. A process-specific ByoGlot marker and recorded own-write identities permit the next capture while password-manager exclusions still block access. Unsupported file/storage, indexed, non-content, private or device-specific formats and snapshots over 64 MB prevent the fallback from copying, preserving the original clipboard. An unavailable or timed-out UI Automation password check also prevents fallback. Bounded native reads reject an oversized raw selection before trimming so a partial selection cannot be translated. Request identities survive cancellation, dismissal and identical repeated source text. Text and API keys are redacted from diagnostic record strings; no app logging or crash dump collection is installed.

The HTTP transport refuses public cleartext endpoints before sending, follows only same-origin redirects, caps response bodies at 8 MB and includes response reading in the total deadline of at most 180 seconds. API keys use current-user DPAPI with origin entropy. Settings and encrypted secrets use atomic file replacement. Once saving a connection starts persistence, cancellation cannot interrupt it; a settings failure rolls the secret back. The portable export contains no keys or history.

Run `dotnet test windows/ByoGlot.Core.Tests` and `dotnet test windows/ByoGlot.App.Tests` on macOS for portable checks. DPAPI tests run only on Windows. Run `dotnet build windows/ByoGlot.App -c Release -p:Platform=x64 -p:AppxPackageSigningEnabled=false` on Windows. Compiler warnings are errors. Portable Core and service tests run locally; Windows CI also exercises DPAPI and native clipboard materialization before building both package architectures. The app has never been launched during this assignment.

The Windows PR workflow produces an unsigned x64 and ARM64 Store bundle and uploads `windows-unsigned-msix`. `windows-release.yml` verifies a `windows-v<Version>` tag and the manifest version, repeats the tests and package build, uploads the `.msixupload` artifact, and attaches it to a draft GitHub release. CI artifacts omit optional debug symbol packages so managed builds do not require native FastLink conversion tools. No tag or release is created during implementation. The owner must match the manifest publisher to Partner Center before submission. Packaging follows the [Microsoft WinUI CI guide](https://learn.microsoft.com/en-us/windows/apps/package-and-deploy/ci-for-winui3); unsigned packages need local test signing before installation.

Manual Windows checklist for Tasks 6 and 7:

These first clipboard scenarios assume the packaged test build is already installed.

1. Start with a link and rich text or image formats on the clipboard, then trigger the copy fallback in VS Code or Chrome while it writes several formats. Expected: the selection translates only after the clipboard settles and the original clipboard formats are restored.
2. Exercise delayed-render Office or Excel content and a target that responds to Ctrl+C after 700 ms. Expected: format rendering and late sequence bumps do not cancel restoration; the captured selection translates and the original content remains available after Quit.
3. After the simulated copy settles, copy different text manually, first from another app and then from the same app. Expected: that newer user copy stays on the clipboard and is never replaced by the backup.
4. Trigger two fallback translations in succession, then click Copy and trigger fallback again. Expected: ByoGlot recognizes its own writes, does not show the private-clipboard message and does not trigger double-copy translation from its own notifications.
5. Keep a password-manager exclusion on the clipboard and trigger fallback. Expected: no snapshot, simulated copy or rewrite occurs, the private-content message appears and password-manager auto-clear still works.
6. Test a hung delayed-render owner and a persistent restore lock. Expected: the UI remains responsive, a timed-out snapshot sends no Ctrl+C even if it completes later, and failed restoration shows a fresh clipboard warning instead of leaving the previous quick-window result visible.
7. On clean Windows 11 accounts meeting build 26300 or later, build Release for x64 and ARM64 with a local test certificate, trust that certificate on the test machine and install the appropriate MSIX. Keep the private certificate outside the repository. Check the package identity and publisher against Partner Center.
8. Launch the packaged app twice and verify one process and one tray icon. Close the main window, reopen it from the tray, check Settings and Quit, and verify startup disabled by default and the Task Manager disabled state.
9. In English and Russian UI, add a provider with explicit origin consent, choose models, translate a sentence, cancel and repeat, copy the result, edit and duplicate templates, and export/import settings. Choose a template with a target language and verify the picker moves to it; then change the picker and verify that language wins. Check navigation after Fix connection and tray Settings, including rejected provider keys. Verify the export contains no API key or user text.
10. Select text in Edge and press Ctrl+Alt+T. Verify the quick window appears by the cursor and typing still goes to Edge until the quick window is clicked. Check Copy, template changes, Open in ByoGlot, pin, Escape and outside-click dismissal.
11. Repeat with Notepad, Word, VS Code, Windows Terminal and a PDF in Edge; record which use UI Automation and which need the copy fallback. Verify original text and non-text clipboard formats survive fallback, source-app exit and ByoGlot Quit. Verify unchanged clipboard data is never rewritten, a newer copy is never overwritten, and fallback with a protected prior clipboard neither copies nor resets password-manager auto-clear. Check Win+V and cloud synchronization for duplicate restoration and Copy entries. With fallback disabled, unsupported apps must show the no-text message.
12. Put an elevated terminal in front and verify the administrator message without copying or translating text. Try an unavailable or already registered shortcut; Settings must show the error while tray commands still work. Restart Explorer and verify the branded tray icon returns.
13. Enable double copy and copy twice in Edge; verify one translation. Copy once in Word while it writes several formats; verify no translation. Verify ByoGlot's Copy and fallback restoration do not trigger translation. Disable double copy and verify notifications stop.
14. Copy protected content from a password manager and choose Translate Clipboard; verify the private-content message and no provider request. Check empty, unchanged and 5001-character clipboard and selection inputs.
15. Use monitors at 100 and 150 percent scaling, including a monitor with a negative origin. Trigger at every edge and verify the quick window fits the cursor monitor's work area.
16. During a slow response, trigger another selection, repeat identical text and dismiss/reopen the quick window. Only the latest request may appear. Confirm the packaged app can still use UI Automation and SendInput; if either fails because of packaging, stop and report that the Store channel needs an unpackaged signed alternative.
17. Confirm the release version and manifest match, then have the owner create the release tag when ready. Download and inspect the `.msixupload`, verify both architectures, and run Windows App Certification Kit. The tag-triggered release workflow itself has not been executed during this assignment.
18.
