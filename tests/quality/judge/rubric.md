# Задание судье: оценка перевода

Ты оцениваешь варианты машинного перевода веб-страницы. Работай только с файлом раунда, который тебе дали. Не открывай другие файлы проекта, не ищи в интернете и не вспоминай существующие переводы этой страницы. Оценивай по оригиналу и своему знанию языка.

## Что такое хороший перевод

Хороший перевод читается как текст, который сразу написали на целевом языке. Для технических страниц эталон это текст, который написал разработчик для разработчиков, а не подстрочник.

- Свобода разрешена: можно делить длинные фразы, менять порядок, выбрасывать пустые слова вроде "actually" и "in fact", заменять обороты на естественные. Если смысл сохранен, это не ошибка.
- Принятый у разработчиков жаргон лучше буквального перевода. Для русского: "бин", а не "bean-компонент"; "резолвер", а не "преобразователь"; classpath можно оставлять латиницей.
- Код в обратных кавычках не переводится и не меняется. Имена продуктов, классов и людей остаются как есть. Названия разделов и статей переводятся.
- Канцелярит, кальки и лишние местоимения (для русского: "является", "посредством", "осуществляется", "данный", "рассмотрите возможность", "вы можете" там, где можно без него, цепочки родительных падежей) это стилистические недостатки.
- Ошибка смысла хуже любой стилистики: потерян или искажен факт, условие, отрицание, число или связь между частями фразы; перевод говорит другое, чем оригинал; кусок текста пропал или появилось то, чего нет в оригинале.
- Текст, оставшийся на языке оригинала там, где его нужно было перевести, и пометка "(нет перевода)" это ошибки.

## Что сделать с каждым блоком

Блок начинается с `## <id>`, дальше идет оригинал `SRC` и варианты под метками A, B, C, D. Если в блоке есть строка `CTX`, это фрагмент, который пользователь выделил на странице, а `CTX` это окружающий текст: его не переводят, он нужен, чтобы понять смысл. Короткий термин или фразу оценивай по тому, подходит ли перевод именно к этому контексту. Метки перемешаны в каждом блоке заново, не ищи закономерность.

1. `ranking`: все метки блока от лучшего к худшему. Если два варианта неразличимы по качеству, все равно расставь их, а в `note` обоих напиши "равны".
2. `labels`: для каждой метки одна оценка и короткое `note` (до 20 слов):
   - `ok`: читается как написанное на целевом языке, смысл точен. Мелкая вкусовщина не мешает `ok`. `note` можно оставить пустым.
   - `style`: смысл точен, но заметно коряво: калька, канцелярит, неестественный порядок слов, неудачный термин. В `note` напиши, что именно.
   - `meaning`: смысл искажен, потерян или добавлен. В `note` напиши, что именно искажено.

В конце файла есть раздел "Короткие строки" со списками S1, S2 и так далее. Каждый список это один вариант перевода всех коротких строк страницы (заголовки, подписи, ячейки). Буквы S не связаны с метками A-D. Оцени каждый список одной-двумя фразами: качество заголовков и согласованность терминов.

## Формат ответа

Запиши JSON-файл по пути, который тебе указали. В `items` должен быть каждый блок файла, без пропусков.

```json
{
  "items": [
    {
      "item": "b34",
      "ranking": ["B", "A", "C"],
      "labels": {
        "A": { "label": "style", "note": "калька 'is meant to be'" },
        "B": { "label": "ok", "note": "" },
        "C": { "label": "meaning", "note": "потеряно условие 'only if'" }
      }
    }
  ],
  "page": {
    "consistency": "как согласованы термины внутри каждого варианта, если это видно",
    "notes": "общие наблюдения по вариантам",
    "termIssues": ["термин: что не так"],
    "shortLists": { "S1": "оценка", "S2": "оценка" }
  }
}
```
